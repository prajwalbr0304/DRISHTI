# Curated public-source Renukaswamy case isolated from synthetic generation

The change reserves the final planned case slot for a deterministic, source-qualified Renukaswamy record and appends it only after synthetic graph, feature, label, and quality generation. It carries provenance flags through source, identity, evidence, case-detail, and UI contracts, with persistent pending-trial/allegation notices and metadata-only public references. The offline golden fixture validates, identical runs produced the same fixture hash, and the curated case receives no build-time feature, label, or prediction rows. Runtime consumers and mutable operational paths do not consistently honor those boundaries, so the integration is not ready to ship.

**Watch for:** **confirmed** inclusion in live corpus embeddings despite the analytics-exclusion marker; **confirmed** presentation of surrogate/proxy identifiers as authoritative case facts; **confirmed** mutation and upload paths that can invalidate metadata-only public-reference semantics; **confirmed** pending-trial notices that remain static while lifecycle status changes; and a **confirmed** timeline regression that hides unmatched legacy milestones.

**Verdict**: NEEDS_CHANGES

## High-level view

The insertion strategy keeps the named case out of build-time synthetic graph, feature, label, and quality generation without consuming the shared RNG. **Confirmed:** that exclusion ends at fixture construction because live corpus refresh still selects directly from every `CaseMaster`, including this record.

The current-version payload lets case detail distinguish public-source data from synthetic fixtures, and global notices keep presumption-of-innocence wording visible across case tabs. **Confirmed:** the primary case identifier remains the surrogate `CaseMaster.CrimeNo`, while court views render the deterministic proxy `CourtID` name despite an explicit instruction not to present proxy authorities as real.

Public references carry source, authenticity, rights, and handling metadata without native files. **Confirmed:** `IsSynthetic=false` and `metadata_only=true` are descriptive only; correction, upload, completion, archive, and link endpoints accept these items without an origin/invariant gate.

The timeline now prefers curated display labels and suppresses exact CaseEvent/CourtEvent duplicates. **Confirmed:** its all-or-nothing `event_backed` fallback removes real arrest and chargesheet dates from a mixed case after any unrelated event-backed record appears.

**Confirmed:** no automated test fixes the curated generator, provenance hydration, exclusion, evidence invariants, notice lifecycle, proxy display, or mixed timeline behavior in place.

<summary>Details</summary>

### Build-time isolation is bypassed by live corpus refresh

The generator completes graph, feature/label, and quality construction before appending the curated record (`datagen/build.py:179-196`), whose snapshot is marked `excluded_from_derived_analytics` (`datagen/curated_cases.py:639-641`). A 2,000-case offline run produced zero curated feature, label, or prediction rows, and same-seed replays produced the same fixture digest.

**Confirmed:** the runtime embedding job does not consult the marker. Both corpus selector branches start from unfiltered `CaseMaster` rows (`services/ml/app/cases/casedata.py:133-148`), then `embed_corpus` persists embeddings and canonical text for those IDs (`services/ml/app/cases/corpus.py:28-46`). The default 12,000-case refresh includes the curated record in a 2,000-case golden fixture, putting named people and pending allegations into a derived vector corpus. Filter both selector branches against the current `CaseVersion` flag and enforce the same condition in `fetch_corpus_batch` or a shared analytics-eligibility view.

### Surrogate crime number remains the primary case identity

The snapshot distinguishes `police_crime_no` from `surrogate_crime_no` (`datagen/curated_cases.py:643-647`). **Confirmed:** the header still takes `detail.core.crime_no` (`web/src/routes/cases/CaseFile.tsx:141`) and the overview labels it “Crime no.” (`web/src/routes/cases/subpages/OverviewPage.tsx:39`). This presents an invented fixture key more prominently than `Crime No.250/2024`, while other `CaseCore` consumers receive the same ambiguity. Hydrate a display reference or surrogate flag, use the official reference on public-source surfaces, and label the 18-digit value as an internal fixture identifier.

### Proxy CourtID is rendered as public court attribution

Every curated `CourtEvent` stores the fixture `court_id`, and `_court_event` attaches the same City Civil and Sessions Court label to every event (`datagen/curated_cases.py:400-414`). The snapshot says `do_not_present_proxy_as_real_authority` (`datagen/curated_cases.py:665-675`). **Confirmed:** casework resolves `court_name` from the proxy foreign key (`services/ml/app/casework/service.py:585-596`), and the court tab renders it as the event’s court (`web/src/routes/cases/subpages/CourtLifecyclePage.tsx:99-104`). Supreme Court and Karnataka High Court milestones can therefore be attributed to an unrelated fixture court; the generic detail label cannot repair event-specific attribution. Store a sourced court label per event, suppress proxy FK names when `reference_mapping=proxy`, and make the UI prefer the sourced label.

### Metadata-only public references remain mutable file targets

Curated evidence declares `metadata_only=true`, `file_backed=false`, and `is_synthetic=false` (`datagen/curated_cases.py:467-472`) and has no `EvidenceObject`. **Confirmed:** `_update_metadata` checks only archive state and ordinary field validity (`services/ml/app/evidence/service.py:358-397`), while `_issue_upload_url` checks only archive state and file validity (`services/ml/app/evidence/service.py:409-425`); completion has no origin or metadata-only check. The UI offers correction and archive actions for any writable item (`web/src/routes/cases/subpages/evidence/EvidenceDetailsDialog.tsx:183-186,278-285`). A caller can remove caveat text/tags or attach a file while the item still claims no native file exists. Reject upload/completion and classification-changing edits for curated metadata-only items, or create a separate synthetic annotation instead of mutating the source reference.

### Pending-trial safeguards are static while lifecycle status is mutable

The snapshot stores `PENDING_TRIAL` in its notice list (`datagen/curated_cases.py:649-656`), and `fetch_case_provenance` materializes notices only from that list (`services/ml/app/cases/casedata.py:225-250,293-294`). **Confirmed:** casework exposes lifecycle actions (`web/src/routes/cases/subpages/CourtLifecyclePage.tsx:38-40,70-79`), then updates `CaseVersion.StatusCode` in place without updating snapshot status or notices (`services/ml/app/intake/service.py:922-925`). A judgment can make status terminal while every case tab still says “Trial pending”; a manually added court judgment can also coexist with pending status. Derive the pending notice from current status/final-disposition state, and require a new source-qualified version—or make the curated snapshot read-only—before changing public procedural claims.

### Event-backed fallback drops unmatched legacy milestones

The revised timeline records CaseEvent types and exact CaseEvent/CourtEvent day keys, but queries legacy `ArrestSurrender` and `ChargesheetDetails` only when `event_backed` is entirely false (`services/ml/app/casework/service.py:776-833,857-873`). **Confirmed:** a case with one registration, bail, or court event but only legacy arrest/chargesheet rows loses those dated milestones even when no corresponding event exists. This accidental regression affects partially migrated operational records beyond the curated case. Always merge legacy anchors and suppress only a semantically matching event for the same milestone/date/person.

### Curated contracts lack regression coverage

**Confirmed:** no test file changes, and repository search finds no coverage for `build_renukaswamy_case`, `fetch_case_provenance`, non-synthetic evidence fields, notice derivation, or analytics exclusion. The existing timeline test covers an event-backed case and a newly created event-free case only (`services/ml/tests/test_casework.py:318-332`), leaving mixed records untested. Add deterministic fixture assertions for case count/RNG stability, origin flags, absence from build-time and runtime derived outputs, API hydration/URL filtering, metadata-only write rejection, notice transitions, proxy display, and mixed timeline reconciliation.

Validation: `git diff --check main` passed; all 12 changed Python files parsed; the 2,000-case golden generator and offline integrity gates passed with 2,000 cases, 20 non-synthetic people, 20 non-synthetic evidence references, and 31 non-synthetic source records; two builds produced the same digest (`aceb67de73ec56e52974b0036c03c27aca1ea06ec8601860759ed540412e70d4`). Backend pytest could not collect because `psycopg2` is absent, and frontend typechecking could not run because dependencies/`tsc` are not installed.
