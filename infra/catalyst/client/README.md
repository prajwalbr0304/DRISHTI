## Hosting choice: Slate (preferred), Web Client Hosting (fallback)

**Slate** is the current Catalyst frontend hosting (Web Client Hosting is
legacy/deprecated). Slate serves the React build from the domain root on
`https://<app>.onslate.in` (IN DC), with preview deploys.

One-time activation: **Console → project → Slate → Start Exploring** (5 s). Then,
from `infra/catalyst` (bound to DHRISTI):

```powershell
# 1. Build the app (production env → .env.production). Regenerates the Slate SPA
#    config inside dist/ and runs the no-secrets bundle scan.
npm --prefix ../../web run build

# 2. Link the existing build as a Slate app (writes the `slate` block in
#    catalyst.json). --default / -ni avoids interactive prompts.
catalyst slate:create --name drishti-web --framework react-vite -ni
#    (or `catalyst slate:link` to link an existing local app interactively)

# 3. Deploy to the Development environment.  $ credit-spending — HELD
catalyst deploy slate -m "drishti web (dev)"
```

**Fallback — legacy Web Client Hosting.** If Slate cannot be activated, the
`client` component in `../catalyst.json` (source `client/`) hosts the same
`web/dist`; deploy with `catalyst deploy --only client`. `client-package.json`
sets `homepage`/`login_redirect` to `/` (paths must start with `/`).

## One public API base URL → API Gateway (no secrets in the bundle)

The app reads its API base at **build time** from `VITE_API_BASE_URL`
(`web/src/config/runtime.ts`). Environment-specific, committed values:

| Env file | `VITE_API_BASE_URL` | Auth mode |
|---|---|---|
| `web/.env.development` | `http://localhost:8000` (FastAPI direct) | `offline` |
| `web/.env.production` | Catalyst **API Gateway** origin + `/api` | `catalyst` |

The deployed base points at the **API Gateway route** in front of the
`gateway_api` function, e.g. `https://<project-domain>/api` (the `/api` prefix is
stripped by `gateway_api` via `DRISHTI_GATEWAY_PATH_PREFIX`). Get the exact origin
from **Console → API Gateway** after `catalyst apig:enable`, then set it as the CI
variable `VITE_API_BASE_URL` (Pipelines) or in `web/.env.production.local`. The
committed `.env.production` ships an **intentionally invalid placeholder**
(`https://REPLACE-WITH-CATALYST-API-GATEWAY-ORIGIN/api`) so an unconfigured
production build is caught by `web/scripts/check-bundle-secrets.mjs`.

**Cross-domain (Slate → Gateway).** Slate (`*.onslate.in`) and functions
(`*.catalystserverless.in`) are different origins, so relative `/server/...`
paths would break — the base URL is **absolute**, requests are sent with
`credentials:'include'`, and each authenticated call attaches a raw
`Authorization` token from `catalyst.auth.generateAuthToken()` (Web SDK v4.6.1+;
**no** `Bearer` prefix — the Catalyst convention). AppSail is **not** a native
gateway/browser target; the browser only ever talks to the gateway. No secret,
`DATABASE_URL`, AWS URL, or signing secret is ever placed in a `VITE_*` var or the
bundle (all `VITE_*` reads centralised in `runtime.ts`; scan enforces it).

## Authentication (matrix row 17)

Login/session uses **Catalyst Authentication** via the embedded Web SDK, wired in
`web/src/auth/` (`catalystWebSDK.js` + `/__catalyst/sdk/init.js`):
`signIn` (embedded login iframe), `isUserAuthenticated` (session check),
`signOut`, `generateAuthToken` (cross-domain token). `<RequireAuth>` gates every
app route; the public landing page (`/`) stays open. A local **offline** mode
(synthetic demo identity) keeps `web` runnable without a live project.

The client never supplies a trusted role: `gateway_api` derives the role
**server-side** from the authenticated identity and forwards a signed context to
AppSail. The client's `X-Role` is a display/audit hint and is stripped at the
gateway. See `../functions/README.md`.

## SPA deep-link fallback, caching, CORS, badge

- **Deep links / refresh:** `web/public/_redirects` (`/* /index.html 200`, plus
  `/app/* /index.html 200`) is copied into `dist/` by Vite;
  `dist/.catalyst/slate-config.toml` (regenerated by
  `web/scripts/postbuild-slate.mjs` after each clean build) carries the same
  redirects. React Router also sends `/app/*` → `/` for the embedded-auth SDK
  redirect (legacy Web Client path).
- **Asset caching:** Vite emits content-hashed assets under `dist/assets/*`
  (safe to cache long-lived; the hash busts on change). Slate serves these via
  its CDN automatically; `index.html` / `_redirects` are revalidated so new
  deploys are picked up. Slate has no `_headers` file mechanism — do not add one.
- **CORS:** the exact deployed Slate origin is added to **Console →
  Authentication → Whitelisting → Authorized Domains** (CORS toggle on). Function
  code sets CORS only for `localhost`; production CORS is gateway-injected (never
  duplicated in code). No wildcard origin.
- **Synthetic Hackathon Demo badge:** `VITE_DEMO_BADGE` ("Synthetic Hackathon
  Demo") is shown on the login gate and in the app shell (`SyntheticBadge`),
  matching the server's `hackathon_mode` / `demo_data_only` posture.
